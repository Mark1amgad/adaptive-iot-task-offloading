# Team Guide

## Where work belongs

- Put member-authored work and received packages in that member's folder under `team-work/`.
- Keep shared research sources in `research/`.
- Keep the reproducible implementation and project experiments in `deliverables/`.
- Keep only concise, decision-relevant validation evidence in `audit_output/`.

## Review rules

- A received archive is not proof that every feature inside it is implemented or validated.
- Preserve source provenance and distinguish code, configuration, and measured output.
- Do not duplicate an unchanged document in multiple folders; link to its canonical copy.
- Do not commit build output, IDE caches, credentials, or empty placeholder directories.
- Changes to task semantics, protocol, metrics, and experiment definitions require review by the affected owners.
